# ADR-0005：投屏副本是设备级缓存，投屏期可达不是新的可见性等级

投屏要求把一份**完全私密**的东西——这支舞的视频副本——放到局域网上，好让接收端自己拉。这与本仓既有的**可见性三级**纪律（完全公开 / 小组公开 / 完全私密）看起来有张力，所以要一次性说清它**不是**什么。

决定：**投屏副本是设备级缓存**，不是产物、不是分享物。它落在应用私有目录下**独立于 `materials/` 与 `susume_share/` 的渲染缓存区**；复用键 = **视频标识 + 渲染勾选档 + 影响画面的设置快照 + 投屏倍速档 + 标注内容指纹**；**每支舞每倍速档一份**，全局设容量上限并按最近使用淘汰；**清空入口放「详细设置」**（首页 ⋯ 进的设备级设置页，那里已经是设备级设置的统一入口）——一行「投屏缓存」显示当前占用与一枚**清空**按钮，清空要确认。它**不随任何 susume 包**（分享的载荷不变）、**不随整机备份**（备份的载荷不变）——两条载荷清单因此一个字都不用改。

**投屏期接收端能拉到那份副本，不等于它进入了任何分享等级**：这层可达只在**投屏会话期内**成立——本机只为这台会话、这一个文件起一个局域网可达的递出通道，路径一次性、会话结束立即停服；副本本身始终是完全私密。换句话说，**可见性三级管的是"进不进包"，投屏管的是"这次会话里谁能拉"，两者不互相定义**。

## Considered Options

- **放进 `materials/`**（练习素材所在）：会与练习片段混层，且素材有自己的自动删除策略与清单，语义不同。
- **放进 `susume_share/`**（出站分享目录）：那个目录正是 FileProvider 覆盖的范围，等于把一份可分享物常驻在盘上；且它会被分享流程的清理逻辑扫到。
- **不缓存，每次投屏现渲**：分钟级等待每次都要重付，用户无法接受；"先投后渲"也无从谈起。
- **随整机备份走**：备份是**完全私密**字段唯一的出口，但缓存是可再生数据，进备份只会让备份包莫名变大。

## Consequences

- 换一支舞、换一个勾选档、换一个倍速档、改了标注，都会命中"未渲染"，需要重付一次渲染时间；界面必须让这件事可见（准备进度 + 各档的准备状态）。
- 渲染缓存区需要自己的容量账（上限、淘汰、清空），不复用素材或分享目录的既有策略。
- 上游一旦需要审计"数据都去了哪"，这份缓存要能被一句话解释：**它只在本机盘上，只在本会话期经局域网可达，随用随弃。**
