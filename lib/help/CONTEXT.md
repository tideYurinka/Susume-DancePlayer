# 帮助与更新 — Context

给用户看的字与拿到新版的路径——新手引导、帮助中心与手册、关于页，以及更新源与下载页。

## Language

**新手引导**:
让新用户第一次就能走完「导入一支舞 → 在播放页练起来」的自动教学，由**引导步**组成，形态四种——**就地讲解**（挖亮被讲的控件、箭头指过去）、**动手演练**（待办条：锚点在屏就贴在跟着目标走的高亮框旁，否则停靠安全区顶；在真实界面上亲手做一遍）、**一次性图文**（居中图文卡）、**短暂提示**（一句话小浮层）。首启＝一次选择 + 一次指认：首次进软件弹一张欢迎图文，选「带我看一遍 / 我先自己用」，最后一步指认「导入视频」或「帮助」入口。只自动出现一次：走完或跳过即记下该单元的状态位，此后再不自动出现；「能再找回来」由**帮助中心**首项那张新手引导页承载——按「起步 / 播放页 / 功能提示」三组逐条显示「已完成 / 未完成」，也承载**引导重置**——清掉某项后走到它的触发点即再演一次。
_Avoid_: 教程（那是帮助中心里与使用手册并列的另一类文档）、教学页、欢迎页、onboarding

**引导重置**:
在新手引导页上清掉新手引导里一个或全部单元的状态位，让它下次走到触发点时再演一次；页顶的「重置所有教程」先问一次再全部清零，一条都没做过时它不显示。重置只动「看过没看过」——舞库、标注、设置、备份、素材一律不变，重置本身也不演出任何东西，清完立即生效、不必重启。
_Avoid_: 恢复出厂（那会连数据一起清）、清除数据、重新引导

**引导步**:
**新手引导**的最小呈现单位：一次只出现一条、只讲一件事。形态四种（**就地讲解** / **动手演练** / **一次性图文** / **短暂提示**）各自独立记状态位，不排队、不重放、互不等待。凡是声明了**锚点**的引导步（**就地讲解**、**短暂提示**，以及声明锚点的**动手演练**步）都以该锚点在当前表面在场为出场前提——锚点不在屏上就不出场、也不被消耗，等它回到屏上接着演；锚点从屏上撤下后不再按它的旧位置画高亮。一个引导单元可含顺序多步：单元内一步关掉才轮到下一步，单元按最后一步置位；多步单元统一带「N/M」步数指示与「跳过」——跳过＝整个单元置位（**动手演练**里的手势演练单元是唯一例外：它跳过不置位，下次走到同一表面再演）。
_Avoid_: 引导页（多页卡片形态的说法）、引导卡片、步骤

**就地讲解**:
挂在具体功能控件上的一句讲解——一句话 + 指向那个东西的箭头。演出时整屏压暗、只把被讲的控件挖亮（高亮框有最小宽度，再细的线也框得住），框里的控件照常可点——框内任一指针按下即算这一步做到（拖动起手也算）：单步或末步即整单元置位，多步则推进下一步；同一下照常落到被指的控件上。点框外任意处即下一步。只在用户真的用到那个功能时才出现，不主动弹、不排队、不重放。单步只有关闭钮；多步各锚在自己那个实物上（如编辑态上手：先指第一段段体、再指第一条分段线的手柄）。
_Avoid_: 引导角标（旧称，统一写「就地讲解」）、气泡引导、红点 / 角标徽标（不带文案的提示点）、新手提示

**动手演练**:
让用户在**自己那支舞**上亲手做一遍的教学形态：**待办条**形如一件“要你做的事”——动作图标 + 待做勾选框 + 一句话 +「N/M」+ 一排进度点 + 带底的「跳过」（末步有多个子勾时，子勾以勾片排在文案下方）。该步声明的**锚点**当前在屏上在场时，待办条贴在锚点那圈高亮框旁：一根箭头指框中心，框在屏幕上半就放框下方、在下半就放框上方，跟着框逐帧重排，且永不与框相交；锚点不在屏上、该步不声明锚点、或只剩驻留的历史矩形时，待办条停靠在安全区顶。高亮框画在锚点矩形外（短边有 24 逻辑像素下限）、跟着目标走，不压暗、不挖洞、不拦触摸（不声明锚点的单元——手势演练——就只有待办条、没有跟随高亮框）。一次只让做一个动作，判「做到了」才算完成：做到当场打勾、停约 0.4 秒再推进，全部做到才置位；跳过则整个单元置位（唯一例外是手势演练单元：跳过不置位，下次重来）。待办条除「跳过」外整条不吃触摸，手势照常落到界面上；演练期间界面行为与平时完全一致——不接管手势、不打断播放、不占用标注数据、不出其它引导。声明了锚点的动手步，其锚点不在当前表面在场时不出场、不被消耗。用在手势演练、编辑态上手（放大与点段体两步）以及分段的选中一步。
_Avoid_: 跟跳（那是跟着视频练舞本身）、演示视频、教学版界面（演练用的就是真界面真手势）

**一次性图文**:
一张图文卡的教学形态——标题 + 一段正文 + 自带按钮，居中弹出、无遮罩，只有卡片自己的按钮可点。按任一按钮即置位；按钮的取值决定后续走向（如首启的欢迎卡与「下载视频」图文，选不同分支最后指认不同入口）。首启那张「下载视频」图文只给**推荐的那一种**下载方法，它与帮助中心「教程 → 下载视频」是同一条内容的两处呈现。
_Avoid_: 弹窗（那指交互组件，如循环提示 / 镜像询问）、欢迎页、教程卡片

**引导文案**:
**新手引导**里给用户看的全部字——单元标题与说明、**引导步**的那一句话、**一次性图文**的按钮标签，以及演出层的固定字串（「下一步」「跳过」「重置所有教程」等）。它只描述怎么说，不描述什么时候说、指向哪里：出场条件、**锚点**、状态位与步序都不由它表达。
_Avoid_: 引导配置、引导数据（那会把结构与文案混成一件事）、文案模板

**帮助中心**:
首页右上角「帮助」入口打开的页面，一页容纳三类内容：**新手引导**（清点与重置）、分章的**使用手册**、以及**教程**分组。它是「复习引导」与「查功能」的唯一入口；播放页的「查看引导」打开的是它的新手引导部分。
_Avoid_: 帮助文档（入口与总称的口语说法，项目内统一「帮助中心」）、教程中心、帮助与反馈、FAQ 页

**使用手册**:
**帮助中心**里的主线文档，按功能域分成七个**手册章节**，每章是一个**文档条目**——以"这功能解决什么问题 + 三步做完"开头，正文是分段分步的文字与截图。
_Avoid_: 说明书、用户手册、产品手册

**手册章节**:
**使用手册**的最小单位——一个功能域一章，一篇可独立编辑的正文（一个**文档条目**）。
_Avoid_: 章节、分类、类目、栏目

**教程**:
**帮助中心**里与**使用手册**并列的另一类文档：每一条是独立的**文档条目**，不隶属任何手册章节。引导里的「下载视频」图文与它是同一条内容的两处呈现。
_Avoid_: 额外文档、扩展教程、教程文档、进阶教程

**文档条目**:
**帮助中心**列表里的一行，也是帮助内容的可独立编辑单位——一个功能域或一件工具一份，含标题、一句说明与正文；正文可分节分步、图文混排。每个**手册章节**是一个文档条目，每条**教程**也是一个。
_Avoid_: 卡片、图卡（单用含义含糊）、帮助文档（入口与总称的口语说法）、文档（单独用含义太泛）

**条目链接**:
**文档条目**正文里指向另一个**文档条目**的链接，写成仓内相对路径（相对本文所在目录），可带 `#标题` 锚点。点一下推入目标条目的文档页并停在锚点，返回回到上一篇；目标可以是手册、教程、关于三组里任意一个已被扫到的条目。`#锚点` 在本文滚动与外部网址交系统浏览器打开是另外两条既有行为，不叫条目链接。
_Avoid_: 跨文档跳转、文档链接、站内链接（口径含糊）、超链接 / 外链（那是外部网址）、锚点链接（那只说 `#` 那一段）

**外部网址**:
**文档条目**正文里带 `http`/`https` scheme 的地址——写成 `[文字](地址)` 或直接写裸网址都算。点一下交系统浏览器打开；打不开（设备上没有浏览器、系统拒绝等）时把地址复制到剪贴板并提示「打不开，已复制地址」。它不加「即将离开应用」的二次确认；不带 scheme（如群号）与带其它 scheme 的地址不走它，点一下只把地址复制到剪贴板并提示「已复制」。
_Avoid_: 外链、超链接（口语，未写明落点）、外部链接（与**条目链接**的 `_Avoid_` 口径混指）、网页链接

**折叠块**:
**文档条目**正文里默认收起、读者点开才展开的一块，用来放"想看才看"的内容（如赞赏码）。一块只有一行标题，收起时块内内容不在屏上；正文里的图铺满整宽，它里面的图按可用宽度的六成居中。
_Avoid_: 折叠区、收起块、折叠面板（那是组件名）、details 块（实现层措辞）、赞赏块 / 赞赏码块（那是用途，不是形态）

**大图查看**:
**文档条目**正文里一张已被渲染的图单击后弹出的全屏层：黑底、图按原比例居中显示、可双指缩放与拖动，顶部写该图的 alt（没有 alt 就不显示这一行）。点层里任意位置（点图与点黑边一个样）、点右上角关闭钮、按系统返回三路都关得掉，关掉回到原处；除那枚关闭钮外不常驻任何按钮。**折叠块**内的图同样适用；缺图不渲染，也就没有这一层。长按正文缩略图或这层大图都直接存进系统相册、不弹菜单。
_Avoid_: 预览图（那指正文里的小图）、图片浏览器（暗示可左右翻页）、放大镜（那指局部放大）、全屏图片页（暗示独立页面）

**关于页**:
首页「⋯」菜单「关于」打开的页面：先交代这个 App 是什么，再给出往下走的三条门——版本、更新说明与**贡献者名单**。它与**帮助中心**并列而非隶属——帮助中心回答「这个功能怎么用」，关于页回答「这是谁做的、装的是哪一版」；「出问题去哪说」由**帮助中心**里的一条**教程**回答。
_Avoid_: 帮助与反馈（关于页不承载反馈入口）、关于我们、About 页、作者页、反馈页

**应用信息头**:
**关于页**与**贡献者名单**页共用的开头：应用图标、应用名与一句话简介，本身不含任何操作。它不随页面变化，正是它让这两页看起来是同一处往下走的两层。
_Avoid_: 页头、应用信息卡（卡片形态的旧说法）、标语栏

**版本行**:
**关于页**上管「有没有新版、要不要装」的那一条：写出本机版本，并给出检查、下载、取消、重试与去放行安装许可的入口。它与**更新提示条**是同一件事的两处呈现——所以开页不自动检查，检查由用户在这里发起。
_Avoid_: 更新行、检查更新按钮（那只是它右端那颗按钮）、版本信息卡

**贡献者**:
为这个 App 出过力而被**关于页**署名的人，一位一条：**贡献者 id**（稳定不变）、显示名、角色，以及可以没有的头像。角色是**贡献者名单**页上标在名字下方的那一行字。
_Avoid_: 开发者（那指整页名单）、作者（**关于页**与**贡献者名单**不再用这个称法）、成员、维护者（那只是角色的一种取值）

**贡献者名单**:
**关于页**推入的页面：开头是与**关于页**同一个**应用信息头**，其下逐位列出**贡献者**，点一位进他的**个人介绍页**。它只列人，不讲这个 App「是什么」——那是**关于页**的事。
_Avoid_: 开发者页、鸣谢页（那是另一件事）、贡献者中心、团队页

**个人介绍页**:
**贡献者名单**里点一位**贡献者**推入的页面：先是他的一小块档案（头像、显示名、角色），其下是这位贡献者自己写的个人介绍。正文用与帮助文档同一套 Markdown 方言。
_Avoid_: 作者页（**贡献者**已取代这个称法）、个人主页、简介页、Profile 页

**更新源**:
应用与**下载页**共同读取的那一处固定地址的来源：本项目自有域名下的一份静态发布面，**版本清单**与按版本归档的安装包都放在那里。它是**发布产物**的落地处，也是应用判断有没有新版的唯一来源；地址在第一个包发出去时就烧进每一个已安装的应用，此后不变。
_Avoid_: 更新服务器、更新接口（那暗示一个会应答的服务）、应用商店（那是另一条分发渠道）、OTA 服务

**版本清单**:
发布端写在**更新源**固定地址上的一页数据，五项——构建号、版本名、安装包体积、安装包地址与更新说明。**构建号是判断有没有新版的唯一依据**：大于本机构建号即有新版，相等或更小即无。应用与**下载页**读的是同一份，因此两处说的永远是同一版。
_Avoid_: 更新信息、版本信息（口语）、latest.json（那是它的落盘文件名，不是概念）

**发布产物**:
一次发布在**更新源**上留下的两件东西：按版本名归档、永久保留的签名安装包，以及被就地覆盖的**版本清单**。两者由同一次发布写出，所以清单里的每一项都描述着同一份包；取回任何一个历史版本只是照着归档路径取。
_Avoid_: 发布包、构建产物（那是 CI 的中间物，不一定发出去）、APK（那是文件形态）

**下载页**:
官网上一页，面向还没装过的人，也是群公告、社交平台与纸质传单上二维码的落点，所以必须是**永远指向当前版本**的固定地址。它按访问设备分两支：安卓上给出当前版本名与安装包体积、一个下载按钮、按钮下一行「目前仅支持 64 位安卓手机」、四步安装引导与「装不上怎么办」，**更新说明**默认收起；iPhone、iPad 与新版鸿蒙上不给下载按钮也不给安装引导，换成一句版本进度说明加一个入群按钮。
_Avoid_: 官网（那是整站）、落地页（外文直译）、下载地址（那只指页面 URL）

**更新提示条**:
根壳左下角的一条常驻浮层：启动后静默检查到有新版本才出现，写明新版本名与安装包体积，带「下载」钮与一个只关本次的 ✕。按下「下载」后它在原地显示进度，可取消；下载失败改为一句人话加「重试」；未获「安装未知应用」授权时改为「需要允许安装未知应用」加「前往设置」，不自动跳转。它有按钮、无停留定时、跨三个 Tab 存活——因此不属于**短暂提示**（只与它共用胶囊视觉）。
_Avoid_: 更新弹窗、更新通知（那会与系统通知混指）、提示条（单独使用含义模糊）
