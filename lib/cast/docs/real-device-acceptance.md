# 投屏地基的真机验收步骤

这一票（#23，规格 #21）在宿主测试里覆盖的是「三条接缝 + 本机假接收端」的全链；
**真接收端的行为只能在真机上看见**。下面是从零到核对完的步骤，与分享面板那条
口径一致：原生与真机行为留真机验收。

## 真机上要验的四件事

1. 能在局域网上发现接收端（SSDP 组播通、设备描述读得出）。
2. 推片后接收端自己播；播放 / 暂停 / 停止 / 跳转 / 音量都对它生效；断开即停服。
3. 我们发出去的 SOAP 指令与 CI 基线是同一串（不是"看起来也能播"）。
4. 三个新增的普通权限在真机上是普通权限：全程没有权限弹窗。

## 前置

- 手机与接收端在**同一个 Wi-Fi、同一网段**；路由器关掉「AP 隔离」「访客网络」
  ——这两样会让 SSDP 组播与递出通道都不通，表现是"搜不到任何接收端"。
- 手机与用来对照的电脑也在同一个 Wi-Fi。
- `adb devices` 能看到手机。

## 路径 A：本机假接收端（零依赖，先跑这条）

1. 在电脑上起一台假接收端：

   ```bash
   dart run tool/cast_fake_receiver.dart --name 客厅电视
   ```

   它会打印设备描述地址与两条控制端点（AVTransport / RenderingControl），并把
   之后收到的**每条 SOAP 指令（动作名 + 请求体原文）**逐条打印。
2. 放行电脑防火墙上的那个 HTTP 端口与 UDP 1900 入站。
3. 手机上打开 Susume，在投屏准备面板里重扫：应能发现「客厅电视」。
4. 投屏。假接收端那边应按下面的顺序打印：

   `GetTransportInfo`（连接探测）→ `SetAVTransportURI` → `Play` → `Pause`
   → `Seek` → `SetVolume` →（查询类）→ `Stop`。

5. 看 `SetAVTransportURI` 的请求体：
   - `CurrentURI` 是本机递出地址，路径形如 `/cast/<一次性随机串>/<文件名>`；
   - `CurrentURIMetaData` 里有 `<upnp:class>object.item.videoItem</upnp:class>`
     与一条 `res protocolInfo="http-get:*:video/mp4:*"`。
6. 核对递出通道的 `Range`（地址就是上面那条 `CurrentURI`）：

   ```bash
   curl -v -H 'Range: bytes=0-1023' '<CurrentURI>'
   ```

   应回 `206` 与 `Content-Range: bytes 0-1023/<总长>`。
7. 在 App 里断开投屏：假接收端应打印 `Stop`；再 `curl` 同一条地址应是
   **连接被拒**（会话结束即停服）。

## 路径 B：rygel（真实 DLNA 接收端）

1. 在一台有桌面的 Linux 上装并起 rygel：

   ```bash
   sudo apt install rygel          # Debian/Ubuntu；Fedora：sudo dnf install rygel
   rygel --disable-transcoding     # 前台跑，看得见日志
   ```

2. 确认它真的在 SSDP 上答（`gupnp-tools` 包提供 `gssdp-discover`）：

   ```bash
   gssdp-discover --timeout=3 | grep -i mediarenderer
   ```

   或者从 rygel 日志里取它的设备描述地址，`curl` 那份 XML 应含
   `urn:schemas-upnp-org:service:AVTransport:1` 与
   `urn:schemas-upnp-org:service:RenderingControl:1` 两个 `serviceType`。
3. 手机与这台机器同网 → Susume 的投屏准备面板里应能发现它 → 投屏后 rygel 端
   开始播放。
4. rygel 的常见脾气：
   - **不给或给错 DIDL 元数据**时它会回 UPnP 错误码（我们给的是最小视频元数据；
     若它拒播，先看日志里具体的 `errorCode`，再核对 `res` 的类型与地址）。
   - 转码开着时它会自己再转一道，比较起播延迟与画面时先 `--disable-transcoding`。

## 怎么核对发出的 SOAP 指令

- **首选路径 A**：假接收端逐条打印动作名与请求体——这就是"我们发出去的是什么"。
- **真接收端**：

  ```bash
  sudo tcpdump -i any -A -s0 'tcp port <递出端口> or udp port 1900'
  ```

  或在 Wireshark 里过滤 `http.request.method == "POST"`，看 `SOAPAction` 头
  （形如 `"urn:schemas-upnp-org:service:AVTransport:1#Play"`）与 `<u:Play>` 元素。
- **期望的动作序列**（与 CI 基线 `test/cast/fake_receiver_e2e_test.dart` 同一份）：

  ```
  GetTransportInfo → SetAVTransportURI → Play → Pause → Seek → SetVolume
  → GetCurrentTransportActions → GetTransportInfo → GetPositionInfo → GetVolume → Stop
  ```

  多一条少一条都说明行为变了。

## 权限核对

```bash
adb shell dumpsys package top.yurinka.susume | grep -i -e ACCESS_NETWORK_STATE \
  -e ACCESS_WIFI_STATE -e CHANGE_WIFI_MULTICAST_STATE
```

三条都应出现。三条都是**普通权限**：投屏全程不应弹出任何权限对话框。

## 路径 C：App 里的可见全链（原片投屏 + 遥控）

这一票（#25，规格 #21）把链路打通到用户可见，**推的是原片、不渲染任何东西**；
渲染类与倍速档留后续票。真机上按这条走一遍：

1. 打开一支舞 → 单击画面唤出控制层 → 顶栏点「**投屏**」。
2. 准备面板里应列出路径 A / B 里的那台接收端；点「重新搜索」应再扫一次。
   - 副本被删掉再打开这支舞时，面板里应出「这支舞的视频副本不在本机…」
     这一句，且不出接收端列表。
   - 电视关掉 / 不在同一 Wi-Fi 时，面板里应出「没找到接收端：手机与电视
     要在同一个 Wi-Fi，电视别开访客网络」这一句，重扫按钮仍在。
3. 选一台：接收端那边应 **1–3 秒内起播原片**（`SetAVTransportURI` → `Play`）；
   App 侧进入**投屏态**：底排标注槽位整排消失、轨道带只剩「分段」一行、
   顶栏五枚——「倍速切换」「画面开关」「断开投屏」「系统镜像」「查看引导」。
4. 在手机上播放 / 暂停 / 拖进度（画面横向滑）/ 选学习段（长按拖选）：
   接收端那边应跟着暂停、复播、跳转——手机上这几项都**同时**作用于电视。
5. 「断开投屏」与左上角退出箭头**同义**：都回编辑态；断开那一刻起，
   递出地址应立刻不可达（`curl` 被拒）。系统返回在投屏态内先断开、
   再按一次才离开页面。
6. 投屏中按手机返回键离开播放页、或回首页换一支舞：会话与递出通道都应
   立刻收干净（接收端打印 `Stop`，递出地址不可达）。

第 4 步的「同时作用于电视」是这一票的遥控范围。

## 路径 D：画面开关与投屏胶囊（#32）

这一票（#32，规格 #21）把投屏态的画面区接管过来：默认**黑底 + 一行指路
提示**（源片不上手机屏），顶栏那枚**画面开关**打开后切到**静音本地预览**。
本地预览件、投屏胶囊与既有手势面的行为在宿主测试里覆盖；真机上要核对的是
**这块屏上的观感与出声**：

1. 投屏后**默认面**：画面区应是纯黑 + 一行「想看画面就打开顶栏的『画面
   开关』」；手机**不发声**——投屏期手机是遥控器，主内核已静音（声音只从
   电视来），也不放源片。
2. 点顶栏「**画面开关**」：画面区出现本地画面（同一支舞、静音）；若电视
   那边已经放了一会儿，本地应从**电视当前的位置**接上，而不是从 0 开始。
   再点一下回黑底。
3. 打开画面开关后**核对出声**：手机仍**不应出声**（电视那份才是声音）；
   电视上贴纸 / 数拍 / 节拍动画照旧，手机上那份画面**只有视频画面本身**。
4. 画面开关打开时，画面上**单指横滑 / 双击**：应当仍然只遥控电视（电视
   暂停 / 跳转），本地预览**不跟着停下或跳走**；底排播放键同理。
5. 收起控制层（**投屏-观看态**）：屏上应只剩一枚「**投屏中 · <接收端
   名>**」胶囊；**点它不产生任何变化**（防误触），点画面（胶囊之外）应把
   控制层展开回来。
6. 「断开投屏」后（或离开播放页）：本地预览应**立刻停住**，画面开关回到
   默认关（下次投屏仍是黑底），**本机声音恢复**（这时本机播放照常出声——
   别把上一段的静音漏在引擎上）。

## 路径 E：系统镜像入口（#33）

本项目**不做屏幕镜像**（ADR-0004）；这枚入口只负责把用户送到系统设置。

1. 进投屏态（路径 C 第 3 步）后，长按顶栏那枚「**系统镜像**」应弹出那句代价
   说明：「整屏镜像：有延迟、手机屏要亮着、控制层也上电视；我们这条路推的是
   渲染好的投屏副本」。
2. 点它：App 应**先断开投屏**（接收端打印 `Stop`、递出地址立刻不可达、界面
   回编辑态），**随后**才跳到系统的「投屏 / 无线显示」设置页——顺序反了就是
   电视上两份画面打架。
3. 把这台设备上的系统投屏设置页停用（或用一台没有该页的设备）再点一次：应
   退到**显示设置**；连显示设置也接不住时，App 里应给一句短暂提示
   （「这台设备打不开系统投屏设置」）——**不是**一个按了没反应的入口。
4. 准备面板「搜不到接收端」的空态里同一条入口在场（同一句文案 + 同一枚
   按钮），点它同样先断后跳；此刻本就没投，断开是幂等空操作。

第 2、3 步里"原生真的能不能打开这两页"只能在真机上看见；Dart 侧的顺序与
降级链由 `test/cast/platform_system_mirror_test.dart` 与
`test/player/cast_mode_test.dart` 钉住。

## 路径 F：投屏入口的门与失败面（#35）

这一票把投屏的门与失败面收口；宿主测试在 `test/player/cast_entry_gate_test.dart`、
`test/player/cast_mode_test.dart`（门与失败分流）、`test/player/cast_run_test.dart`
（递出通道异常路径、电视端停止）里逐条钉住，**真机上要看的只有「那枚入口在什么时候
灰、按下去说什么」与「断线时它回到什么样子」**。

1. 五条门：**置灰，但仍按得动**——按一下只弹一句原因，动作绝不发生
   （不弹准备面板、不起通道、不连接收端）：
   - 把副本删掉再打开这支舞：投屏入口置灰，按一下弹「这支舞的视频副本不在本机，
     先把副本找回来再投屏」。
   - 进对比态并起录（含准备期）：投屏入口置灰，按一下弹「录制中（含准备中）
     不能投屏，先停录」。
   - 进对比-控制层 / 取景调节态：投屏入口置灰，按一下弹「先退出对比或取景调整，
     再投屏」（取景调节态里控制层是收起的，先退出取景再看那枚入口）。
   - 打开「音画同步」气泡（校准会话活着）：投屏入口置灰，按一下弹
     「音画同步校准中，先退出校准再投屏」。
   - 渲染进行中：投屏准备面板渲起投档那一段、以及投上之后后台渲其余倍速档
     那一轮（#31）都记这位事实；灰的观感与那句「正在渲染投屏副本，渲完再投」
     在宿主测试里核对，真机上对着准备面板看一眼即知。
2. 失败分流：搜不到 / 被拒**只给一句短暂提示**、停在编辑态；失联 / 电视端停止
   **回编辑态**再给短暂提示：
   - 电视关掉 / 不在同一 Wi-Fi：准备面板里是空态说明（重扫仍在眼前）。
   - 推片被拒（假接收端可让 `SetAVTransportURI` 回 SOAP Fault）：App 里弹
     「没接上这台接收端」，仍停在编辑态，递出地址不可达。
   - 投屏中把电视那头按停：手机退后台再回前台（App 回前台会问一次接收端状态），
     App 应回编辑态并弹「投屏断了，回到编辑态」，递出地址立刻不可达
     （系统返回在投屏态内先断开、再按一次才离开页面）。
3. 换视频 / 离开播放页：会话与递出通道都应立刻收干净（接收端打印 `Stop`，
   递出地址不可达）——触发点收在既有复位一处。

## 路径 G：App 里的渲染链（#26：勾选档 + 拍声 + 缓存 + 进度/取消）

这一票把**声音类**打通：只勾声音类时视频流原样复制、音轨重编码并把拍声混进去
（秒级）；勾了画面类走重编码（#26 只有「归一帧率与像素格式」的底链，#27 已把
镜像闸门插进链首，#28 已把取景窗口插在镜像之后，#29–#30 再插贴纸 / 数拍）。
渲染与缓存都只在真机上真跑，宿主测试用脚本化执行器接缝 + 临时目录覆盖。

1. 打开一支舞 → 顶栏「投屏」→ 准备面板：
   - 两个勾选「画面类」「声音类」应**默认全选**，下面那句应是「画面要重编码：
     预计分钟级；改一次设置就要重渲一次」；
   - 只留「声音类」→ 那句应变成「只重做音轨：拍声混进去，秒级出结果」；
   - 两个都取消 → 那句应变成「不渲染：直接把原片推给电视，不用等」。
2. **只勾声音类**选一台接收端：面板应出进度条（百分比随渲染前进），
   几十秒的素材应在秒级完成；完成后自动进入投屏态，电视上放的是副本。
   - 电视上应**听得见拍声**，且与手机本地播放同一套拍声、同拍
     （`assets/sounds` 三段资产）。
   - 面板渲染中点「取消渲染」：面板回到接收端列表、不进入投屏态；应用支持目录
     下的 `cast_render/` 里**不应留下半成品**（`.mp4.part` 与 `.clicks.wav`）。
3. **再投同一支舞、同一勾选档、同一倍速档**：面板应**不再渲染**（秒进投屏态）
   ——那是缓存命中；这是「命中不重渲」在设备上的样子。
4. 改动**任一**会影响产物的东西（全局镜像 / 局部镜像总开关 / 取景 / 备注 /
   分段线 / 半拍线 / 拍点 / 节拍音量 / 音源）之后再投：应**重新渲染**一次
   （缓存键里那五个分量任一变了）。
5. **全选（画面类 + 声音类）**再投一次：这次应明显是分钟级，且产物在电视上比
   原片略软（多一代有损压缩，见下面的已知偏差）。
6. 渲染中途按手机返回键 / 杀掉 App 再回来投：`cast_render/` 里不应留半成品，
   下次投同一档照常重渲。

## 路径 H：镜像与实际显示逐帧一致（#27：全局镜像 + 局部镜像）

这一票的宿主侧是**纯件直测**：滤镜节点按片段钉住，且与画面方向库（手机上实际
显示的那一份取值）逐格同判——见 `test/cast/cast_mirror_gate_test.dart` 与
`test/cast/cast_render_plan_test.dart`。**「电视上的翻转与手机上实际显示的逐帧
一致」只能在真机上比对**（本票验收第 5 条）。

前置：一支有局部镜像片段的舞（在镜像工具里加一段，例如 00:02–00:06）。

1. 电脑上跑宿主对照（它按 ADR-0004 的像素级验收口径生成「翻过 / 未翻」两份
   参考帧并按 PSNR 判）：

   ```bash
   dart run tool/cast_render_bench_host.dart --out /tmp/cast_bench
   ```

   报告里镜像闸门一项应通过：**窗内那一帧像未翻的原片、窗外那一帧像翻过的
   原片**，两个端点帧（t=2 与 t=4）按半开区间判——终点算窗外。
2. 手机上走真正的投屏：勾「画面类 + 声音类」、**全局镜像开**、局部镜像片段
   00:02–00:06。电视上应是：00:02–00:06 这段**不翻**（两枚闸门相消），
   段外**整片翻**。
3. 逐帧抽查（本票第 5 条验收）：
   - 手机播放头停 00:04（窗内）截整屏，再从副本的同一位置导一帧；
   - 在**画面区域内**比对：两者应同相（都是「未翻」的那一份），
     `ffmpeg -i <手机截图> -i <副本导帧> -lavfi psnr -f null -` 的 `average`
     高于 30dB；拿「翻过的那份参考帧」去比则明显更低；
   - 再把同一比对放在 00:08（窗外）做一次：这时两边都应是「翻过」的那一份
     （只剩全局那一枚闸门），PSNR 同样高于 30dB；窗外与手机同相却是未翻，
     说明全局那一枚没装上；窗内与「翻过的那份」更像，说明局部那一枚没生效。
4. 倍速档复核：选 0.5 档再投一次，窗仍应落在 00:02–00:06（**源时间轴**上的
   区间），不随倍速漂移——闸门排在 `setpts` 之前就是这个缘故。

## 路径 I：取景与实际显示逐帧一致（#28：源画面取景）

这一票的宿主侧是**纯件直测**：裁切窗口的四边按「读回产出的表达式 → 套到源尺寸」
与取景纯域的 `framingSelectionRectOnPicture`（画面上那块矩形的那一份数学）同判，
取景与镜像的先后按**源时间轴逐帧逐点**与手机显示模型同判——见
`test/cast/cast_framing_gate_test.dart`（含一条「错序立刻分歧」的反证）与
`test/cast/cast_render_plan_test.dart`。**「电视上就是手机里圈好的那块画面」只能
在真机上比对**（本票验收第 2 条）。

前置：一支**取景选区偏在一侧**的舞（例如左缘 1/8、右缘 1/2），并有一段局部镜像
片段（例如 00:02–00:06）。**选区必须偏心**：居中的选区在两种先后下同相，判不出
顺序（这也正是本票最要防的那一档）。

1. 手机上走真正的投屏：勾「画面类 + 声音类」、**全局镜像开**、局部镜像片段
   00:02–00:06。
2. 窗内（手机播放头停 00:04）截整屏，再从副本同一位置导一帧，在**画面区域内**
   比对：两者应同相（两枚闸门相消 = 未翻），
   `ffmpeg -i <手机截图> -i <副本导帧> -lavfi psnr -f null -` 的 `average`
   高于 30dB；且**裁出来的那一块**与手机上那块同位置、同宽高比（选区自己的宽高比
   就是上屏画面的宽高比）。
3. 窗外（00:08）同样比一次：这时两边都应是「翻过」的那一份（只剩全局那一枚）。
4. **顺序复核（本票最容易错一档的地方）**：拿同一个窗内的时刻，从源副本生成两份
  参考帧并各比一次 PSNR：

   ```bash
   # 先翻、再按源坐标切窗（手机那一式，副本应更像这一份）
   ffmpeg -y -ss <t> -i <源副本> -vf "hflip,crop=<w>:<h>:<x>:<y>" -frames:v 1 ref_flip_then_crop.png
   # 先按源坐标切窗、再翻（错序，副本不应更像这一份）
   ffmpeg -y -ss <t> -i <源副本> -vf "crop=<w>:<h>:<x>:<y>,hflip" -frames:v 1 ref_crop_then_flip.png
   ```

   副本应与 `flip_then_crop` 那一份更像（PSNR 明显更高）。**偏心的选区上两份参考帧
   本身差异很大**（差在「切的是源画面哪一半」），所以这条比对是能判的。
   （实现期在宿主 ffmpeg 4.4.2 上跑过一次这条比对：正确式约 60.9dB、错序约
   1.3dB——与两份参考帧自身的差异同量级。）
5. **未取景 / 整帧取景**各投一次：产物应与原片同画面（除多一代压缩），既没有
   裁切痕迹、也没有多余的缩放（同一台电视上画面占比不变）。
6. **兜底**：把 marker 文件里 `meta` 段的取景四边手改成一个奇数像素落点与一个
   极端比例（例如 `left=0.5001, right=0.5002`），再投一次：产物仍应被接收端播出
   ——`ffprobe -show_streams` 应两路流齐、宽高都是偶数且不小于 2。

## 路径 L：数拍与节拍动画按实际显示渲染（#30）

这一票把**逐拍静态数字**接进画面链：一格一张同尺寸 PNG（由播放页按**上屏同一份
样式**光栅化，见 `player/cast_beat_sheet.dart`），按**各自的时长**写进一份
`-f concat` 清单——整条序列当**一路输入**喂给一个 `overlay`（不是上百拍上百路
`-i`：宿主实测 300 个节点在 1080p/5s 上就要 0.85s，是同一段素材纯编码的几倍）。
**摆锤与动画一像素都不进副本**（规格：呈现类只烤逐拍静态数字）。宿主侧分两层覆盖：

- **纯件直测**：`test/player/cast_beat_placement_test.dart`（视口 → 画面区域的
  换算：四格记忆、尺寸系数、贴边、退化输入）、`test/player/beat_count_layout_test.dart`
  与 `test/player/cast_beat_sheet_test.dart`（数字行的量测与上屏那一行逐项同值、
  画布只含底衬、四角透明、各格同尺寸、空窗全透明）、`test/player/cast_render_wiring_test.dart`
  （逐拍文字与手机**同一次求值**、落位进缓存键、不装的几种情形）、
  `test/cast/cast_beat_gate_test.dart` 与 `test/cast/cast_beat_plan_test.dart`（清单
  正文、`-f concat` 输入、节点位置与层序、贴纸输入下标顺延）、
  `test/cast/cast_render_orchestrator_test.dart`（逐格图与清单落盘、收尾必删）。
- **宿主逐像素对照**（本节的第 1–3 步）：

  ```bash
  dart run tool/cast_beat_check_host.dart --out /tmp/cast_beat
  ```

  它拿**生产那一串命令行**（只把编码器换成本机 libx264）跑本机 ffmpeg，再从产物里
  **按帧号**读像素（帧网格的边界上按时间取帧会有取整歧义——这一点在脚本里写明了）。

**真机上要核对的是**：字体与位置观感（宿主对照用的是几何色块，不是字）、电视上
是否看得清，以及「与手机同一时刻一致」的逐帧比对（第 4 步）。

1. **落位与尺寸**（与手机同源）。宿主对照里：数拍那一块在成片帧里的**像素矩形**
   与「声明的归一化中心 + 尺寸分数」独立算出的期望逐边偏差 ≤ 3 像素。真机上核对：
   手机上数拍那一行压住的位置，电视上同一处也该是它（按**画面区域**归一化比对）。
2. **逐拍时间窗**（半开 `[起, 止)`，且序列不提前结束）。宿主对照逐帧验：**窗的
   第一帧在、前一帧仍属于上一格**，两侧各多查一帧；不显示的格（前导区之前、
   末拍之后）画面上那一块**原样**——不进任何像素；末格时长生效（最后一帧仍是它）。
3. **一行数字，不是动画**。宿主对照与纯件两层都钉：数拍层只有**一个** `overlay`
   节点、没有逐拍 `enable` 节点、没有 `drawtext`/`drawbox`；产物里那一块就是数字行
   的底衬（画布尺寸 = 数字行 + 内边距，**不含**动画位那一格高度）。
4. **真机观感与同一时刻一致**：一支带数拍（含组上标过 4 的那一段）的舞，勾
   「画面类 + 声音类」投屏：

   - 电视上的八拍号 / 拍号 / 组上标应与手机**同一时刻**同一个号（数字是渲染那一刻
     按数拍锚点链算的，烤死之后不随遥控跳段重锚定——**已接受的偏差**，面板上那句
     「数拍数字按渲染那一刻算…」说的就是它）；
   - 手机播放头停某一拍截整屏，再从副本同一位置导一帧，在**画面区域内**比对：
     数字应落在同一处（按画面区域归一化），号也相同；
   - 0.5× 档再投一次：位置与号不变（时间窗排在 `setpts` 之前，窗不随倍速漂移），
     只是每一格在电视上放得更久。

### 两条环境事实（写给后来者）

- **已链接的 ffmpeg 变体里没有 `drawtext`**：`ffmpeg_kit_flutter_new_min` 零外部库
  （README 的启用库表里 min 一列是 `-`；`com.antonkarpenko:ffmpeg-kit-min:2.2.2` 的
  `libavfilter.so` 里 `drawtext` / `subtitles` / `ass` 都没有，`libavfilter.so` 里
  只有 "freetype is not available, ignoring fontfile option." 这句）。所以规格里
  「单输入的时间窗文本」在这条依赖上落成了**播放页光栅化的图像序列 + 一个叠加节点**：
  文字那一层的「与上屏同源」由 `player/cast_beat_sheet.dart` 复用上屏样式常量兑现，
  时间窗仍是**每一拍一条**（写在清单的 duration 里）。要改回真 `drawtext`，先换
  ffmpeg 变体（`video` / `full` 才带 freetype），那是一次独立的依赖决策。
- **`-f concat` 清单的最后一格要重列一次**（`duration` 描述前一条文件，末条没有
  后继就早退），这一条由 `test/cast/cast_beat_gate_test.dart` 逐字钉住。

## 已知偏差（不是缺陷）

- 投屏副本比源片**多一代有损压缩**，电视上会略软于手机本地播放。
- **本地预览是另开的一只播放器**（与主内核并列、构造即静音）：它按接收端
  **上报**的位置起播，之后就按本机时钟自己走；起播那一刻的误差与之后的
  漂移由接收端的 `Seek` 精度决定，界面不做「已对齐」之类的承诺。
- 倍速靠换文件，**起播等待（约 1–3 秒）与 Seek 精度由接收端决定**，界面不做承诺。
- 数拍数字与节拍动画是**渲染那一刻**算出来的，遥控跳段不会重锚定它们
  （`#30` 的副本里**只有逐拍静态数字**：摆锤与动画不烤；数字在末拍之后不再显示，
  与手机上「位置晚于末拍即无拍可数」同判）。
- 数拍那一行**按画面区域归一化**落到副本上：手机上若把浮层停在画面之外（信箱黑边
  里），副本里没有那块地方，它会贴到最近的画面边（与备注贴纸同款钳制）。
- **#26 的副本范围是整片**（首线→尾线那段范围与画面滤镜链同处，随「从 0 整片
  解码 + 时间窗偏移」一并落；#27 只落了镜像闸门、#28 只落了取景窗口，范围仍未落）；
  电视上的时间轴与手机本地播放逐位对齐，用户设的首尾线暂不影响副本范围。
- **取景副本的帧尺寸 = 选区那一块**（不是源片尺寸）：电视上看到的是「圈好的那块
  画面」按选区自己的宽高比铺满屏，与手机上那块画面的比例一致；手机屏与电视屏的
  宽高比差由接收端 contain 承担，不烤进产物。

## 路径 J：投屏倍速档（#31）

这一票把**一档一份副本、换文件切换**做到用户可见：投屏只认 0.5 / 0.75 / 1
三档，**倍速不靠接收端**（DLNA 没有这门能力），切换就是让接收端**换一个文件
播**。宿主测试在 `test/cast/cast_speed_tier_test.dart`（纯件换算）、
`test/player/cast_speed_run_test.dart`（后台渲、换档、回退）、
`test/player/cast_prep_panel_test.dart` 与 `cast_mode_test.dart`（面板与顶栏）
里逐条钉住；真机上要核对的是**接收端真的换得动、等待有多久、跳得准不准**。

1. 准备面板里「投屏倍速档」三枚多选：默认**只勾**与当前手动倍率最接近的
   那一档（手动倍率 1.3 → 勾 1×）。至少留一档；都不勾渲染档时三枚置灰、
   只剩原片这一档。
2. 勾上两三档再投屏：**当前档先渲好即开投**（不必等其余档），投上之后其余档
   在后台接着渲——投屏态顶栏首枚「倍速切换」点开，能看到各档「正在播」/
   「准备中 xx%」/「可切」/「等着渲」。
3. 真机上核对换档：点一枚已渲好的档，电视应在**1–3 秒内**换到那一份并续播
   （接收端打印 `SetAVTransportURI` → `Seek` → `Play`）；手机画面上的位置
   读数与电视是**同一支舞的同一处**（0.5× 档上「源片第 10 秒」= 电视第 20 秒，
   这是换算过的，不是错位）。
4. 学习段：先选一段练着，再换档——电视应接在**这一段之内**（段尾换算后仍是
   段尾），不会因为换档跑到段外。
5. 失败面：把递出地址掐掉（或让接收端拒绝新的 `SetAVTransportURI`）再换档——
   电视应**回到上一档**继续放，App 里弹「换档没成功，回到上一档」；断线那条
   更狠的收场仍走「投屏断了，回到编辑态」。
6. 断开投屏 / 换视频 / 离开播放页：后台还在渲的那些档应**立刻停掉**（不必等它
   渲完），不留半成品。

第 3、5 步的起播等待与跳转精度**由接收端决定**（1–3 秒是经验值，不是承诺）；
这一票的文案已经把这句话摆在「倍速切换」面板里。

## 路径 K：备注贴纸按实际显示渲染（#29）

这一票把**备注贴纸**接进画面链：贴纸是**第二路输入**（播放页侧按上屏同一份
span 与样式光栅化出来的带 alpha 单帧 PNG），落在**取景之后、倍速 `setpts`
之前**，靠 `overlay` 的时间窗在贴纸自己的时段里出现。宿主侧分两层覆盖：

- **纯件直测**：`test/cast/cast_sticker_gate_test.dart`（落位与上屏那一份数学
  `noteStickerRect` 逐点比、半开时间窗、镜像分段无漏无重、帧率网格归一、
  alpha 路径的形状与「乘不是设」）、`test/cast/cast_render_plan_test.dart` 与
  `test/cast/cast_render_orchestrator_test.dart`（命令行与产物文件）、
  `test/player/cast_sticker_sheet_test.dart`（PNG 的尺寸、alpha、点名取色）、
  `test/player/cast_render_wiring_test.dart`（标注 → 第二路输入的装配）。
- **宿主逐像素对照**（本节的第 1–3 步）：

  ```bash
  dart run tool/cast_sticker_check_host.dart --out /tmp/cast_sticker
  ```

  它拿**生产那一串命令行**（只把编码器换成本机无损 libx264）跑本机 ffmpeg，
  再从产物里逐帧读像素。

**真机上要核对的是**：字体与点名取色（宿主对照用的是几何色块，不是字）、
电视上的观感与尺寸是否「看得清」，以及贴纸翻面的时机是否与手机逐帧一致。

1. **落位与尺寸**（与手机同源）。宿主对照里：贴纸墨迹在成片帧里的**像素矩形**
   与「声明的归一化中心 + 尺寸分数」独立算出的期望逐边偏差 ≤ 3 像素；
   取景 + 局部镜像那两跑里，贴纸在片段内横向取反（`x → 1 - x`）、片段外不取反
   ——这正是手机上 `noteStickerCenterOnFace` 的两支。
   真机上核对：手机上贴纸压住的那个舞者/杂物，电视上同一处也该被压住；
   取景偏在一侧时，贴纸跟着取景窗口换算（不是按源画面原相落位）。
2. **进出时刻**（半开 `[起, 止)`）。宿主对照逐帧验：窗的第一帧在、窗的**终点
   那一帧不在**，两侧各多查一帧——不多一帧不少一帧。真机上看进出那一帧的
   观感（两处都在同一帧上进出）。
3. **透明度与 alpha 路径**。宿主对照的硬判据：
   - 墨迹内部与 `α·PNG像素 + (1−α)·背景色` 的最大偏差 1.6/255——透明度是
     **乘**上去的；
   - 反例（`overlay=alpha=premultiplied`，即把直通 alpha 当预乘读）同一处偏差
     96.4——这条比对判得出「乘不是设」；
   - 滤镜图形状：第二路 `format=rgba` 进、`scale2ref` 缩完再送回 `rgba`、
     `overlay=…:format=rgb` 混合、单帧输入不配 `-loop`、全命令不配 `-shortest`、
     第二路显式 `fps=30` 归到主片帧率网格。
   已知偏差（**不是缺陷，如实留档**）：产物链尾的 `format=yuv420p` 自己会在
   贴纸外沿糊一格（色度 2×2），因此宿主对照里「近边 3 像素那一圈」的平均偏差
   两条路都在 30/255 量级、且默认路径（`yuva420p` + 默认混合）并没有更差——
   这一圈只留读数、不作判据；「边缘无脏边」在**产物格式内**是格式本身的限制，
   我们这条路保证的是**混合那一层**逐像素精确（上面第一条）。
4. **真机观感**：一支带 2–3 条备注（含一条点名）的舞，勾「画面类 + 声音类」
   投屏：
   - 电视上的贴纸文字与点名颜色应与手机上**同一份样式**（同一套 span 与字号：
     字号 = 基准字号 × 该条备注的等比系数，随系统字号缩放）；
   - 大小按「占上屏画面矩形的比例」铺开——手机上贴纸占画面多大一块，电视上就
     占多大一块（与源分辨率、投屏倍速档都无关）；0.5× 档下位置与大小不变；
   - 贴纸进出与手机上同一时刻（半开窗）；
   - 手机上的**画面开关**打开时，本地静音预览只画视频画面本身（贴纸只在电视上）
     ——与 `lib/cast/CONTEXT.md` 的「画面开关」词条同一口径。
5. **与上屏同源的一句话**：贴纸的字形、点名取色与双层描边不是照着手机再写一遍，
   而是**复用上屏那三层 span 与同一个样式构造器**
   （`note_sticker_overlay.dart` 的 `noteStickerFillSpans` /
   `noteStickerStrokeSpans` / `noteStickerOuterStrokeSpans` +
   `noteStickerTextStyle`）——这条是代码事实，由 `cast_sticker_sheet_test.dart`
   的用例钉住（点名段取代表色、正文恒白、alpha 通道留着、余量透明）。
